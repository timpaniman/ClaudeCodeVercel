# 17기 파일럿 운영 가이드

> 목적: 재학생 17기를 첫 사용자로 초대해 실제 사용에서 문제를 찾고, 문제가 없으면 졸업생 1~16기(약 500명)로 넓힌다.
> 성공 기준(Plan): 1개월 내 가입 완료율 70% · MAU 40% · 모바일 접속 60% 이상 · 드라이브 자료 100% 이전.
> 이 문서의 ☐ 는 교수님(또는 운영진)이 확인하는 항목, 「Claude」 는 개발 쪽에서 준비하는 항목입니다.

## 1. 시작 전 준비 (T-7일 ~ T-1일)

### 1-1. 운영 환경 (module-7 배포와 함께)
- ☐ 운영용 Supabase 프로젝트 생성 (**포털 전용**, 리전 서울). 개발 프로젝트는 Python RAG 앱과 공유 중이라 운영에 쓰지 않는다.
- ☐ 운영 프로젝트에 `supabase/bundle/all.sql` 실행 (007 포함 여부 확인: `npm run db:bundle` 로 최신본 생성)
- ☐ Resend 가입 → 발송 도메인 인증(SPF/DKIM) → Supabase **커스텀 SMTP** 로 연결 (기본 메일 서버는 시간당 발송 한도가 매우 낮아 500명 초대에 쓸 수 없다)
- ☐ Supabase 이메일 템플릿(`supabase/email-templates/`) 교체, Site URL·Redirect URLs 를 운영 도메인으로, Email OTP Length 6
- ☐ Vercel 환경변수 등록: Supabase 3종, `NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_OTP_LENGTH`, `RESEND_API_KEY`, `EMAIL_FROM`, `UNSUBSCRIBE_HMAC_SECRET`, `CRON_SECRET` (개발용 `EMAIL_PROVIDER=log` 는 넣지 않는다)
- ☐ 교수님 관리자 프로필 생성 (`role=admin, status=active`), 교수님 Gmail 로 로그인 시험

### 1-2. 자료·명단
- ☐ 17기 명단 CSV 작성: `이메일, 이름, 기수(17)` — 양식은 관리자 화면 명단 메뉴의 "양식 다운로드". **이메일이 수강생이 실제 로그인에 쓸 주소인지** 확인한다(개인/회사 메일 혼용이 가장 흔한 실패 원인).
- ☐ 관리자 화면 → 명단 → CSV 올리기 → 미리보기(오류·중복 행 확인) → 확정
- ☐ 드라이브 자료 이전: `npm run migrate:scan` → 만들어진 `manifest.csv` 에서 기수·제목 검수 → `npm run migrate:import`(미리보기) → `--apply`. 자료는 항상 **미공개**로 들어가므로, 관리자 화면 자료 목록에서 확인 후 "미공개 전체 선택 → 공개" (알림 없음)
- ☐ 17기 수업 자료 최소 1건, 환영 공지 1건 게시 (처음 들어온 사람이 빈 화면을 보지 않도록)

### 1-3. 점검 (Claude)
- ☐ 「Claude」 운영 환경에서 RLS 테스트·기본 흐름(로그인 → 자료 열람·다운로드 → 공지 → 프로필) 통과
- ☐ 「Claude」 iPhone Safari·Android Chrome 에서 로그인, 홈 화면 추가, 자료 다운로드 확인

## 2. 초대 (T일)

### 2-1. 단톡방 공지문 (초안)

> 안녕하세요, 장동인 교수입니다.
> 우리 기수 전용 **AI4CEO 포털**을 열었습니다. 수업 자료와 공지를 한곳에서 바로 찾아보실 수 있습니다.
>
> 1. 아래 주소를 **Safari(아이폰) 또는 Chrome(안드로이드)** 에서 열어 주세요. (카카오톡 안에서 열면 로그인이 이어지지 않을 수 있습니다)
> 2. 수강 신청 때 사용한 **이메일 주소**를 입력하고 "인증 코드 보내기"를 누릅니다.
> 3. 메일로 온 **숫자 코드**를 입력하면 끝입니다. 비밀번호는 없습니다.
> 4. 로그인 후 "나" 탭 → "홈 화면에 추가"를 하시면 앱처럼 쓰실 수 있습니다.
>
> 주소: `https://(운영 도메인)`
> 메일이 안 오거나 "승인 대기"로 나오면 이 방에 남겨 주세요.

### 2-2. 당일 운영
- ☐ 발송 후 30분 간격으로 관리자 화면 확인: **가입 완료율**, **승인 대기**
- ☐ "승인 대기"에 뜬 사람 = 명단 이메일과 다른 주소로 가입한 경우. 신청 기수·이름을 보고 **승인**(기수 지정) 또는, 명단 이메일을 바로잡고 안내
- ☐ 메일이 안 온다는 문의: ① 스팸함/프로모션 탭 ② 명단에 적힌 주소와 같은지 ③ 1분 뒤 재전송 (메일 서비스는 같은 주소에 60초 간격 제한)

## 3. 1~2주차 관찰

관리자 화면(대시보드)에서 매주 확인한다.

| 지표 | 어디서 | 기준 |
|------|--------|------|
| 가입 완료율 | KPI "가입 완료율" | 1주 50%, 1개월 70% 이상 |
| MAU(최근 30일 접속자) | KPI "최근 30일 접속자" ÷ 활성 회원 | 40% 이상 |
| 모바일 비율 | "모바일 vs PC" 도넛 | 60% 이상 (접속 **횟수** 기준) |
| 인기 자료 | "인기 자료 Top 10" | 어떤 자료가 실제로 쓰이는지 |
| 알림 발송 | "이메일 알림" 최근 작업 | 실패 0 |

- ☐ 첫 자료·공지를 올릴 때 "이메일 알림 발송"을 켜고 **실제 수신 확인** (스팸함 포함, 수신 해제 링크 동작)
- ☐ 막힌 곳을 한 줄씩 기록한다(누가·어디서·무엇이 안 됐는지). 2주 뒤 우선순위를 정하는 근거가 된다.

## 4. 피드백 (2주차 말)

수강생 5~8명에게 직접 묻는다.

1. 로그인에서 막힌 적이 있었나요? (어느 단계에서)
2. 원하는 자료를 찾는 데 얼마나 걸렸나요? 단톡방/드라이브와 비교하면?
3. 알림 메일은 적당했나요? (너무 많음 / 적당 / 못 받음)
4. 글씨 크기·버튼 크기는 편했나요?
5. 가장 아쉬운 점 한 가지는?

## 5. 확대 여부 결정 (Go / No-Go)

**Go** — 모두 만족할 때
- 가입 완료율 70% 이상(또는 미가입자 사유가 이메일 불일치 등 운영으로 해결 가능한 것)
- 로그인·다운로드 실패 신고 0건(재현되는 결함 없음)
- 알림 메일 도달 문제 없음

**No-Go** — 하나라도 해당하면 수정 후 재파일럿
- 권한 오류(다른 기수 자료가 보이거나 반대로 자기 기수 자료가 안 보임)
- 알림 메일이 스팸 처리되거나 대량 실패
- 40~60대 사용자가 반복해서 막히는 화면

**확대 순서 권장**: 최근 졸업 기수(16기, 15기) 2~3개 → 이상 없으면 나머지 기수. 기수별로 명단 CSV 를 올리고 초대문을 보낸다. 한 번에 500명을 초대하지 않는다(메일·지원 부담 분산).

## 6. 문제 발생 시

| 증상 | 조치 |
|------|------|
| 특정 사용자 로그인 불가 | 관리자 화면 명단/승인 확인 → 이메일 불일치면 명단 수정 또는 승인 |
| 잘못 공개한 자료 | 자료 목록에서 "비공개"로 전환 (즉시 목록·다운로드에서 사라짐) |
| 알림 메일 잘못 발송 | 이미 나간 메일은 회수할 수 없다. 공지로 정정 안내. 그래서 알림 켜기 전 미리보기·수신자 수 확인 |
| 사이트 장애 | Vercel 대시보드에서 이전 배포로 롤백 |
